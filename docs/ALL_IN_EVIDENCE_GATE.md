# Receipt-based all-in cost evidence gate (offline)

Run `node --test bench/all-in-evidence.test.mjs` from the repository root. This is a deterministic integer-wei calculator; it does **not** retrieve receipts or prove that input evidence is authentic.

Import `compareEvidence` from `bench/all-in-evidence.mjs`. Both baseline and candidate must supply the same chain ID and the same recipient addresses and net recipient balance deltas (decimal wei strings). Each side must include nonempty successful transaction receipt records with unique transaction hashes, `gasUsed`, and `effectiveGasPrice`. Provide all five additional cost fields, explicitly setting zero only if verified not applicable: `relayerWei`, `dataWei`, `settlementWei`, `authorizationWei`, `deploymentWei`. The evaluator rejects missing fields and negative/fractional numbers.

**Accounting contract:** receipt gas cost = sum(gasUsed × effectiveGasPrice). Extras must exclude any charges already represented in receipts; otherwise double counting invalidates comparisons. For rollups, include L1 data charges only if absent from receipt gas accounting. Include all relayer remuneration, offchain service charges converted to wei with an explicitly documented rate, deployment amortization, and cross-chain settlement overhead. If amounts are on different chains/tokens, do not pass them to this calculator as if they were comparable: first create an independently auditable common-unit valuation and document price/time/source. Actual signed EIP-7702 authorization transactions and full calldata must be captured, not estimated from isolated gasleft probes.

Before interpreting output as measured savings, verify canonical receipts and sender/recipient pre/post balances independently, archive block hashes, chain IDs, authorization lists, signed intents, relay compensation, timestamp, client version and source revision. This script cannot perform these steps. It compares supplied data only and should never be used alone to claim >45% savings.
